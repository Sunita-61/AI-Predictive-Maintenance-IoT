# Dataset Documentation & Setup

## Overview

This project uses the synthetic **AI4I 2020 Predictive Maintenance Dataset**, an industry-standard benchmark reflecting real predictive maintenance scenarios encountered in milling machine operations.

- **Primary Source (UCI Machine Learning Repository):**  
  [https://archive.ics.uci.edu/dataset/601/ai4i+2020+predictive+maintenance+dataset](https://archive.ics.uci.edu/dataset/601/ai4i+2020+predictive+maintenance+dataset)
- **Dataset Size:** 10,000 observations × 14 features
- **Class Imbalance:** Approximately 3.39% failure observations (`Machine failure = 1`) and 96.61% non-failure observations (`Machine failure = 0`).

---

## Directory Organization

```
data/
├── raw/                 # Immutable original dataset files as downloaded
│   └── ai4i2020.csv     # (User places downloaded file here)
├── processed/           # Cached or engineered datasets (reproducible via scripts)
│   └── .gitkeep
└── README.md            # This documentation file
```

### 1. `data/raw/` (Raw Data)
- **Purpose:** Stores the original, untouched dataset as obtained from the data source.
- **Rules:**
  - **Do not modify** raw files directly.
  - Raw data files are excluded from git version control via `.gitignore` to prevent repository bloat and comply with repository redistribution best practices.
  - Recommended filename: `data/raw/ai4i2020.csv`.

### 2. `data/processed/` (Processed Data)
- **Purpose:** Stores any cleaned, split, or transformed datasets generated by project scripts.
- **Rules:**
  - All files in this folder are reproducible by running the data preprocessing pipeline.
  - Never hand-edit processed artifacts.

## How to Download and Set Up the Dataset

1. Visit the [UCI Machine Learning Repository AI4I 2020 Dataset Page](https://archive.ics.uci.edu/dataset/601/ai4i+2020+predictive+maintenance+dataset).
2. Download the `ai4i2020.csv` dataset file.
3. Save or move the file to:
   ```bash
   data/raw/ai4i2020.csv
   ```
4. Verify the setup using the project CLI:
   ```bash
   python main.py check
   ```

## Dataset Schema & Feature Definitions

| Column Name | Type | Description | Role in Modeling |
| :--- | :--- | :--- | :--- |
| `UDI` | Integer | Unique identifier (1 to 10000) | **Drop** (Arbitrary ID) |
| `Product ID` | String | Variant letter (L/M/H) + serial number | **Drop** (High-cardinality ID) |
| `Type` | Categorical | Product quality variant (`L`=Low 50%, `M`=Medium 30%, `H`=High 20%) | **Input Feature** (One-Hot Encoded) |
| `Air temperature [K]` | Float | Ambient air temperature in Kelvin (~300 K) | **Input Feature** |
| `Process temperature [K]` | Float | Process temperature in Kelvin (~310 K) | **Input Feature** |
| `Rotational speed [rpm]` | Integer | Spindle rotational speed calculated from power | **Input Feature** |
| `Torque [Nm]` | Float | Torque output around 40 Nm | **Input Feature** |
| `Tool wear [min]` | Integer | Accumulated tool wear time in minutes | **Input Feature** |
| `Machine failure` | Binary (0/1) | Primary target indicator (1 if machine failed) | **Target Variable (Label)** |
| `TWF` | Binary (0/1) | Tool Wear Failure mode | **Target Leakage: EXCLUDE** |
| `HDF` | Binary (0/1) | Heat Dissipation Failure mode | **Target Leakage: EXCLUDE** |
| `PWF` | Binary (0/1) | Power Failure mode | **Target Leakage: EXCLUDE** |
| `OSF` | Binary (0/1) | Overstrain Failure mode | **Target Leakage: EXCLUDE** |
| `RNF` | Binary (0/1) | Random Failure mode | **Target Leakage: EXCLUDE** |

## Critical Machine Learning Safeguards

1. **Target Leakage Prevention:**  
   The failure-type columns (`TWF`, `HDF`, `PWF`, `OSF`, `RNF`) indicate specific failure mechanisms. Including them when predicting `Machine failure` causes severe data leakage, resulting in artificially inflated metrics that fail in real-world deployment. These columns are strictly excluded from model feature sets.

2. **No Uncalibrated Horizon Claims:**  
   The AI4I dataset contains point-in-time machine states, not a survival time series. The model functions as a **state-based failure risk classifier**, not a guaranteed future-horizon prognostic model (e.g., "will fail in exactly 48 hours").

3. **Simulated vs. Real Data:**  
   Any synthetic telemetry generated for dashboard demonstrations must remain clearly labeled as **simulated** and must not be represented as actual physical hardware readings.
